# การกำหนดพื้นที่แผนก (2026-10-02)

ระบบที่ใช้งานจริงอยู่ใน C:/xampp/htdocs/timeguard_admin และ timeguard_api; ไม่ได้คัดลอกกลับ backend ใน workspace ตามคำขอผู้ใช้

- department_work_areas แทนการกำหนดพื้นที่รายพนักงาน: department_area_id, department_id, area_id, is_primary, effective_date, end_date, status
- พนักงานทุกคนรับพื้นที่ของแผนกปัจจุบันโดยอัตโนมัติ รวมถึงพนักงานที่เพิ่มใหม่หรือย้ายแผนก
- employee_work_areas เดิมเปลี่ยนชื่อเป็น employee_work_areas_legacy เพื่อเก็บข้อมูลเดิม ไม่ใช้อนุญาตลงเวลา
- หนึ่งแผนกมีพื้นที่หลักที่ active ได้หนึ่งรายการ และพื้นที่รองหลายรายการ; ไม่อนุญาตรายการพื้นที่เดียวกันที่ช่วงวันทับกัน
- endpoint ใหม่ location/get_department_areas.php; endpoint เก่าคงไว้เพื่อรองรับแอปเดิม แต่คืนพื้นที่จากแผนก
- การลงเวลาปกติต้องอยู่ในขอบเขตมหาวิทยาลัยที่ตั้งค่าไว้ และพื้นที่แผนกที่ใช้งานได้ในวันนั้น; คำขอนอกสถานที่ที่อนุมัติยังใช้ข้อยกเว้นเดิม
- แผนที่แสดง layer ส่วนกลางด้านล่างและพื้นที่แผนกด้านบน เปิด/ปิดแต่ละ layer ได้ การซ้อนทับขึ้นกับพิกัดจริง
- พื้นที่ส่วนกลางที่ปิดใช้งานแสดงเส้นประเพื่ออ้างอิงเท่านั้น ต้องเปิดใช้งานและเลือกเป็นขอบเขตมหาวิทยาลัยที่หน้าพื้นที่ปฏิบัติงานก่อนใช้ลงเวลาปกติ

HR: กำหนดพื้นที่แผนก → เพิ่ม → เลือกแผนก → เลือกพื้นที่ของแผนก → กำหนดประเภทและวันที่ → บันทึก
วาด polygon ของแต่ละแผนกในหน้าจัดการพื้นที่ปฏิบัติงานก่อน แล้วนำมากำหนดให้แผนก

การเปลี่ยนฐานข้อมูลนี้ได้รับคำขอจากผู้ใช้โดยตรง ตารางอื่น Google UID และประวัติลงเวลาไม่เปลี่ยน ข้อมูลส่วนกลางไม่ถูกเปิดใช้งานอัตโนมัติ
สำรองฐานข้อมูลไว้ใน build/backups ก่อน migration; สำรองไฟล์ PHP/JS ที่เปลี่ยนไว้ใน build/department-area-change/file-backup
ตรวจเฉพาะ syntax และผล migration ไม่ได้รันชุดทดสอบเต็มตามคำขอ
